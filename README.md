# CANShift Mobile

Companion app for the CANShift dashboard: live BLE telemetry, laps and the
dash's critical alerts on your phone. See the
[CANShift organization](https://github.com/CANShift) for the full system overview.

📖 **[Documentation](docs/README.md)** — what the app does today, and how BLE
pairing works.

**Stack:** Expo SDK 54 (bare workflow via prebuild) · React Native 0.81.5 ·
React 19.1 · TypeScript 5 · Zustand 5 · `react-native-ble-plx` 3.5.1 ·
`expo-secure-store` 15 · React Navigation 7. Styling is plain `StyleSheet`
with the tokens in `src/theme/ui-tokens.ts` (dark only, system fonts, Menlo
numbers). The design spec is [docs/redesign/HANDOFF.md](docs/redesign/HANDOFF.md).

## Status

iOS-first, Android secondary. iPad is intentionally disabled
(`supportsTablet: false`). The Android build works but receives less
manual testing than iOS — file issues if anything breaks.

## Quickstart

```bash
cd canshift-mobile
npm install
npx expo prebuild --clean   # regenerates ios/ and android/ from app.json
npm run ios                 # build & launch on iOS simulator/device
npm run android             # build & launch on Android emulator/device
```

`ios/` and `android/` are gitignored — they are regenerated by `expo prebuild`
from `app.json` and the `plugins/` config. All persistent native config
lives in `app.json`.

Other scripts: `npm run lint`, `npm run typecheck`, `npm test`, `npm run format:check`.

### Disabling Bluetooth in development

Launching on a physical iPhone spins up CoreBluetooth immediately, which
activates Bluetooth on the device. To suppress that during a dev session, set:

```bash
EXPO_PUBLIC_DISABLE_BLE=1 npm run ios
```

The BLE service then uses an inert manager — no CoreBluetooth activation, no
scanning, no permission prompts. `isBleAvailable()` returns `false` and the app
behaves as it does when the native module is absent (Expo Go). Unset (the
default) restores full Bluetooth.

## BLE protocol

The mobile app talks to the firmware-side GATT server in
[`canshift-firmware/src/hal/ble/ble_server.cpp`](https://github.com/CANShift/canshift-firmware/blob/main/src/hal/ble/ble_server.cpp).
UUIDs and the compact telemetry key map are mirrored in
`src/constants/ble.ts` — keep both sides in sync when characteristics change.

### UUIDs

| Constant               | UUID                                   |
| ---------------------- | -------------------------------------- |
| `BLE_SERVICE_UUID`     | `4fa0b6a0-0000-0000-0000-000000000001` |
| `BLE_CHAR_TELE`        | `4fa0b6a0-0000-0000-0000-000000000002` |
| `BLE_CHAR_STATUS`      | `4fa0b6a0-0000-0000-0000-000000000003` |
| `BLE_CHAR_SETTINGS`    | `4fa0b6a0-0000-0000-0000-000000000004` |
| `BLE_CHAR_CMD`         | `4fa0b6a0-0000-0000-0000-000000000005` |
| `BLE_CHAR_TIMER_CMD`   | `4fa0b6a0-0000-0000-0000-000000000006` |
| `BLE_CHAR_TIMER_STATE` | `4fa0b6a0-0000-0000-0000-000000000007` |
| `BLE_CHAR_TIMER_LAP`   | `4fa0b6a0-0000-0000-0000-000000000008` |
| `BLE_CHAR_ALERT`       | `4fa0b6a0-0000-0000-0000-000000000009` |

Device-name filter on scan: `CANShift`.

### Characteristics

- `BLE_CHAR_TELE` — notify; the binary telemetry frame from `@canshift/core`
- `BLE_CHAR_STATUS` — read + notify; firmware version, CAN health
- `BLE_CHAR_SETTINGS` — read/write; dash brightness (10–100)
- `BLE_CHAR_CMD` — write; command channel (`ack_alert`, `track_state`, console commands)
- `BLE_CHAR_TIMER_*` — the dash-synced lap timer
- `BLE_CHAR_ALERT` — read + notify; the binary alert frame from `@canshift/core`
  (`decodeAlertFrame`). Without it (older firmware) the phone decides alerts
  from core's default danger bands.

### Telemetry key map

Compact keys are intentionally short to keep notifications under the BLE MTU.
Full map (matches firmware `addSignalIfValid()` calls):

| Key   | Label            | Unit |
| ----- | ---------------- | ---- |
| `r`   | RPM              | —    |
| `tps` | Throttle         | %    |
| `map` | MAP              | kPa  |
| `bst` | Boost            | bar  |
| `iat` | Intake Air       | °C   |
| `ct`  | Coolant          | °C   |
| `ot`  | Oil Temp         | °C   |
| `op`  | Oil Pressure     | bar  |
| `fp`  | Fuel Pressure    | bar  |
| `lam` | Lambda           | λ    |
| `s`   | Speed            | kph  |
| `g`   | Gear             | —    |
| `bat` | Battery          | V    |
| `mi`  | Active MAP index | —    |

`mi` (active MAP index) has no display label or unit and is not shown.

### Service shape

`BleService` is a class with an app-wide singleton plus bound free-function
exports for source-compatible call sites (`scan`, `stopScan`, `connect`,
`disconnect`, `pushSettings`, `readSettings`, `sendCmd`, `cancelReconnect`,
`getBlePermissionState`, `isBlePowered`, `tryReconnectLastDevice`). Tests
construct `new BleService({ managerFactory, requestAndroidPermissions })`
with stubbed deps (#301).

## Auto-reconnect & last-device persistence

Tunables (module-level constants in `ble.service.ts`):

| Knob                     | Value |
| ------------------------ | ----- |
| Initial backoff          | 1 s   |
| Max backoff              | 30 s  |
| Backoff factor           | 2     |
| Jitter ratio             | ±20 % |
| Max attempts             | 6     |
| Per-attempt scan timeout | 5 s   |

The last-connected device id is persisted in `expo-secure-store` at the key
`canshift.lastBleDeviceId` (`src/services/last-device.ts`). On startup the
app calls `tryReconnectLastDevice()`; the `useReconnectStore` exposes
`isReconnecting`, `attempt`, `maxAttempts`, and `deviceId` so the reconnecting
banner can show "Values are paused. Try n of m." while the loop runs.
Reconnect is cancelled on user-initiated scan, manual disconnect, or after
the attempt cap is reached.

## Android notes

Bundle id (`expo.android.package`): `ch.tmbk.canshift`.

Install-time permissions are declared in `app.json > expo.android.permissions`:

- `BLUETOOTH`, `BLUETOOTH_ADMIN` — pre-Android-12 BLE
- `BLUETOOTH_CONNECT`, `BLUETOOTH_SCAN` — Android 12+ BLE
- `ACCESS_FINE_LOCATION` — required by some OEMs alongside legacy BLE perms

On **Android 12 (API 31) and newer**, the runtime flow lives in
`src/services/ble-permissions.ts` (#296). On the first scan or connect,
`requestAndroidBlePermissions()` calls `PermissionsAndroid.requestMultiple`
for `BLUETOOTH_SCAN` + `BLUETOOTH_CONNECT` and returns a discriminated
union the UI can switch on exhaustively:

```ts
type AndroidBlePermissionResult =
  | { kind: "granted" }
  | { kind: "denied" }
  | { kind: "never_ask_again" }
  | { kind: "not_applicable" };
```

`ScanScreen` renders an "Open Settings" CTA when the result is
`never_ask_again`. Android < 12 returns `not_applicable` because the
install-time permissions cover BLE there.

## Plugins

Configured in `app.json > expo.plugins`:

- **`./plugins/withGlogFmtFix`** — local config-plugin shim that downgrades
  `fmt`/`glog` Pods to `gnu++17` so iOS builds compile under Xcode 26 /
  clang 26 (where `__cpp_consteval` triggers `FMT_USE_CONSTEVAL=1` and
  breaks the format-security path).
- **`react-native-ble-plx`** — `isBackgroundEnabled: false`,
  `modes: ["peripheral", "central"]`,
  `bluetoothAlwaysPermission` matching the iOS Info.plist string.
- **`expo-secure-store`** — backs the last-device id persistence above.
- **`expo-audio`** — plays the bundled critical-alert tone; configured to request
  no microphone permission.

## canshift-core integration

`@canshift/core` comes from npm (`^10.2.0`). Mobile consumes the binary
telemetry and alert frames, the BLE STATUS and timer schemas, the shift-light
and sensor danger-band defaults, and the lap detector from core; the local
`src/constants/ble.ts` owns the compact telemetry key map.
